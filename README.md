# booking-bot — Telegram-бот для приёма заявок на бронирование

Единая точка входа для запросов: квиз бронирования (даты → гости → тип →
витрина → пожелания → контакт), FAQ без участия администратора, приём
доп. услуг, эскалация живому оператору, уведомление администратору с кнопками
подтверждения, интеграция с Bitrix24, напоминания клиенту, метрики пилота.

**Деплой (VPS+Docker / Windows-автозапуск): см. [DEPLOY.md](DEPLOY.md).**

## Быстрый старт

```bash
pip install -r requirements.txt
copy .env.example .env        # Windows (bash: cp .env.example .env)
# в .env обязательно: BOT_TOKEN (от @BotFather) и ADMIN_CHAT_ID (узнать: @userinfobot)
python app.py
```

При первом запуске создаётся `data/bot.db` с демо-фондом (8 домиков),
услугами, FAQ и доступностью на 60 дней — бот работает сразу «вживую».

Проверить себя: отправьте боту `/id`, затем пройдите сценарий «🏠 Забронировать».

## Настройка (.env)

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен от @BotFather (обязательно) |
| `ADMIN_CHAT_ID` | chat_id чата, куда падают заявки и эскалации (обязательно) |
| `ADMIN_USER_IDS` | id админов, которым доступны подтверждение заявок и /metrics (через запятую; узнать свой — команда `/id`) |
| `BITRIX_WEBHOOK_URL` | вебхук Bitrix24 `https://portal.ru/rest/1/CODE/` — иначе лиды не уходят, заявки всё равно сохраняются |
| `PMS_API_URL` / `PMS_API_KEY` | API PMS (Bnovo/Travelline/Shelter) для автосинка доступности |
| `GOOGLE_SHEET_ID` / `GOOGLE_CREDS_FILE` | fallback-синк из Google Sheets (нужен `pip install gspread`) |
| `SMTP_*` | email-дубль уведомлений (необязательно) |

Приоритет источника доступности: **PMS → Google Sheets → локальная таблица**
(синхронизация каждые 30 минут, `integrations/pms.py`).

## Команды администратора

| Команда | Что делает |
|---|---|
| `/start` | список команд (для админов) |
| `/metrics` | метрики пилота: доля автоответов, конверсия, очередь |
| `/bookings` | последние заявки |
| `/confirm N` / `/decline N` | подтвердить/отклонить заявку (дублирует кнопки в уведомлении) |
| `/reply ID текст` | ответить клиенту в живом диалоге |
| `/export` | CSV истории обращений за 30 дней (для BI) |
| `/id` | свои id (нужны для ADMIN_USER_IDS / ADMIN_CHAT_ID) |

## Структура

```
app.py                  точка входа: polling + фоновые задачи
config.py               чтение .env
db.py                   SQLite-схема и запросы (порт в PostgreSQL — внизу)
bot/
  __init__.py           сборка диспетчера, порядок роутеров
  states.py             состояния FSM (квиз, эскалация)
  keyboards.py          главное меню и inline-клавиатуры
  calendar_kb.py        inline-календарь дат
  booking.py            квиз бронирования (машина состояний)
  handlers.py           меню, FAQ, услуги, эскалация, админ-команды
integrations/
  bitrix24.py           создание лида (3 ретрая)
  pms.py                синк доступности: PMS → Sheets → локальная таблица
  notify.py             Telegram-чат админам, ответ клиентам, email
services/
  booking_service.py    приём заявки: гость → бронь → CRM → уведомление
  followups.py          напоминания за 3/1 дня, «заброшенные» заявки 24/48 ч
  metrics.py            отчёт метрик + CSV-выгрузка
data/bot.db             создаётся автоматически
```

## Данные (SQLite → PostgreSQL)

Схема в `db.py` один-в-один повторяет проектную PostgreSQL-структуру:
`guests, units, bookings, availability, services, booking_services,
touchpoints, faq_articles, followups`. При переходе на PostgreSQL замените
соединение в `db.py` на `psycopg` (запросы уже параметризованы) —
`pip install psycopg[binary]`.

## Демо → боевые данные

1. **Номерной фонд**: отредактируйте `DEMO_UNITS` в `db.py` или вставьте
   строки в таблицу `units` (SQL/админ-скрипт).
2. **FAQ**: замените `DEMO_FAQ` — это и есть «85% типовых вопросов».
3. **Доступность**: подключите PMS (рекомендуется) или ведите Google Sheets
   с колонкой `id` и колонками-датами (0 = занято, иначе цена).

## Метрики пилота

`/metrics` считает: долю обращений, обработанных ботом (цель 85%),
конверсию заявок в подтверждения (цель +28% к базе), эскалации,
очередь неподтверждённых, отправленные follow-up. Базовый замер «12 мин на
заявку» сделайте до запуска бота — сравнивать нужно с ним.
